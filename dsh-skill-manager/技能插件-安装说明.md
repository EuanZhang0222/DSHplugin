# DSH 技能管理器 - 安装说明

## 一、插件是什么

「技能管理器」让你在 DeepSeek Harness 的设置页里**自定义技能（skill）**。技能本质是一段注入模型
system prompt 的指令文本，模型在合适的时候会遵循它行动。

一个技能可以包含：

| 能力 | 说明 |
| --- | --- |
| 正文（Markdown） | 技能指令，可指引模型调用任意可见插件工具 |
| Python 脚本 | 可多个、可配解释器命令，模型按需用 `pwsh` 执行 |
| @技能名 互调 | 正文里引用其它技能，加载时自动展开（循环防护） |
| @api:工具名 | 正文里引用 api 插件里配置的接口，展开为接口说明 |
| @db:连接名 | 正文里引用 database 插件里保存的连接，展开为只读查询指引 |
| SQL 正文 | 正文里直接写 ```sql 代码块，配合 @db:连接名 执行查询 |
| 能力引用 | 下拉选择接口工具 / 数据库连接 / SQL 命令，等价于上面的内联写法 |
| 批量导入导出 | 选择部分或全部技能生成迁移文件，在另一套已安装相同插件的 DSH 环境直接导入 |

配置后**立即生效**，技能持久化到 `~/.dsh/skills/`。

## 二、安装（推荐一键脚本）

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

### macOS / Linux

```bash
chmod +x install.sh && ./install.sh
```

脚本会做两件事：

1. 把插件复制到 `$DSH_HOME/profiles/node_modules/dsh-skill-manager`；
2. 在 `$DSH_HOME/profiles/<profile>/cordis.patch.yml` 登记一行 insert（`inject: [skills, webServer]`）。

## 三、生效方式

- 若 `dsh web` 正在运行：DSH 会**自动热加载** cordis.patch.yml，刷新浏览器（Ctrl+Shift+R）后
  打开「设置 → 技能」即可。
- 若未自动生效：重启 `dsh web`（Ctrl+C 停掉后再运行 `dsh web`）。

## 四、手动安装

如果一键脚本不可用，手动执行等价步骤：

1. 复制插件目录到 `$DSH_HOME/profiles/node_modules/dsh-skill-manager`；
2. 在 `$DSH_HOME/profiles/<profile>/cordis.patch.yml` 中追加：

```yaml
- insert:
    - id: dsh-skill-manager
      name: dsh-skill-manager
      inject: [skills, webServer]
```

3. 重启 `dsh web` 或依赖热加载，刷新浏览器。

## 五、卸载

1. 删除 `$DSH_HOME/profiles/node_modules/dsh-skill-manager` 目录；
2. 从 `$DSH_HOME/profiles/<profile>/cordis.patch.yml` 移除该插件的 insert 条目。

> 已配置的技能文件保存在 `~/.dsh/skills/`，卸载插件**不会**自动删除；如需彻底清除，
> 请一并删除该目录下由本插件创建的技能文件。

## 六、依赖

本插件 host 半部仅依赖 DSH web profile 内置的 `skills` 与 `webServer` 服务，无额外 npm 依赖，
安装门槛最低。

## 七、使用提示

- 新建技能后，可在对话里用 `/技能名` 手动触发，或让模型在合适时机自动加载。
- 技能正文里写「遇到 X 用 Y 工具处理」即可让模型调用任意已启用的插件工具。
- 技能互调用 `@技能名`；被禁用的技能不会被引用。
- 引用接口用 `@api:工具名`（工具名在 api 插件的「API 调用」设置页里可查）；引用数据库用 `@db:连接名`。
- SQL 可直接写在正文 ```sql 代码块里，配合 `@db:连接名` 标注在哪个连接执行；最终由 database 插件
  注册的 `query_database` 工具执行（连接名 / 连接 id 都能匹配，仅放行只读语句）。
- Python 脚本默认用 `python` 解释器，可在技能里改成 `python3` / `py` / 绝对路径。

### 批量迁移到另一套 DSH 环境

1. 勾选要迁移的技能，点击「导出选中」，得到 `.dshconfig.json` 配置文件。
2. 在目标环境安装相同技能插件，打开「技能」页面。
3. 选择冲突策略：
   - 跳过已有项：保留目标环境同名技能；
   - 覆盖已有项：用导入内容替换同名技能；
   - 创建导入副本：保留两份并自动生成 `原名称-copy` 等新名称。
4. 点击「导入配置」并选择文件，完成后核对页面提示及技能引用。

使用「创建导入副本」时，同一配置包内的 `@技能名` 互相引用会同步改写为副本名称。
迁移文件包含完整技能正文、Python 脚本、SQL 和能力引用，但不包含 API 密钥或数据库密码。
目标环境仍需另行导入或配置同名 API 工具与数据库连接。若正文或脚本中手工写入过敏感值，
该内容也会随文件迁移，导出前应检查配置文件。

## 八、依赖关系（跨插件）

- 本插件 host 半部仅依赖 DSH web profile 内置的 `skills` 与 `webServer` 服务，无额外 npm 依赖。
- 「接口引用 / @api:」依赖 **api 插件**（`@deepseek-ai/dsh-api-tools`）已安装并配置了接口。
- 「数据库引用 / @db: / SQL 查询」依赖 **database 插件**（`@deepseek-ai/dsh-database-connections`）
  已安装并配置了连接、注册了 `query_database` 工具（database 插件 1.0.0 及以上版本）。
