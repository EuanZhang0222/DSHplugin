# 数据库统一语义层插件 2.1.0——安装、升级与回滚说明

## 2.1.0 全量分页升级要点（2026-08-28）

- 本版安装文件是 `deepseek-ai-dsh-database-connections-2.1.0.tgz`。升级前备份当前代码；无需恢复旧语义设置，也不需要迁移现有连接、数据集和关系。
- 页面入口：数据集详情 → 浏览数据。完整分页器支持总条数/总页数、数字页码、输入页码直接跳转、每页20/50/100/200行、上一页/下一页与重新查询；数据表独立滚动。总页数待采集成功后确定，改变页大小回到第一页并重新计算页数；关闭窗口释放查询缓存。
- 大模型入口仍为 `query_database_dataset`（查询数据库数据集）。第一次发起完整只读查询，后续用nextCursor（下一页游标）连续读取；limit是每页大小，最高200，不再是总结果上限。
- 调用方必须判断complete（是否读到末尾），并处理collecting/failed/budget_exceeded（采集中/失败/预算不足）和rowFragment（超长行无损分片）。旧脚本如果只取一次rows（当前页）需要升级。详细协议与示例见设计文档第10节。
- 本机本轮回滚备份：`插件备份/database_全量分页开发前_20260828_140310.zip`和`database_正式副本_全量分页开发前_20260828_140310.zip`。回滚安装上一版2.0.0包，或停止服务后恢复正式副本中的代码；不要用旧配置覆盖用户新建数据集。
- 查询缓存存在宿主临时目录，默认合计1 GiB、最多8个查询、采集10分钟超时、空闲1小时过期。资源不足会明确失败而不是截掉尾部数据；需要更大范围应按互不重叠条件分批。进程崩溃可能留下临时文件，重启后的旧游标失效。
- 只扩大数据集查询链路，不解除敏感/停用字段和数据库权限，不改变连接管理手写SQL的200行/15秒诊断限制。全量数据可分次获得，不代表无限数据能同时装入模型上下文。

## 2. 前置条件

- DeepSeek Harness 的 web profile（网页运行配置）可正常启动。
- Harness 必须提供 `settings`（设置）、`webServer`（网页服务）和 `tools`（智能体工具）服务。
- 使用大模型识别时还需配置 `llm`（大模型）服务；没有该服务时连接、数据集、规则引擎、人工关系和智能体查询仍可使用。
- 目标环境能访问 MySQL 或 ClickHouse，建议为插件创建只读数据库账号。
- 升级前停止正在执行的数据集查询和关系识别任务。

## 4. 安装或升级

在包含 DSH 命令的终端执行：

```powershell
dsh plugin --profile web add "C:\path\deepseek-ai-dsh-database-connections-2.1.0.tgz"
```

如果 `dsh` 不在 PATH（命令搜索路径）中，使用实际 Harness 安装目录的命令入口：

```powershell
node "<Harness安装目录>\apps\cli\lib\bin.js" plugin --profile web add "C:\path\deepseek-ai-dsh-database-connections-2.1.0.tgz"
```

安装完成后完整重启 Harness。浏览器端脚本由 client roster（客户端模块清单）加载，仅刷新页面不能替代宿主重启。

本机正式配置的包管理器是pnpm 11.7.0，需使用Harness自带Node目录中的pnpm（例如`C:\APP\deepseek\tools\node-v24.19.0-win-x64\pnpm.cmd`）。若出现`ERR_PNPM_UNEXPECTED_STORE`（缓存版本不一致），先核对原`.modules.yaml`记录的版本并选择对应包管理器，不要通过强制重装全部依赖解决。本轮没有改动宿主全局pnpm配置。

## 5. 从 1.0.0 升级的兼容行为

- 原 `connections`（数据库连接）数组继续使用，旧配置缺少语义字段时自动补默认值。
- 原连接 CRUD（增删改查）、测试、浏览、只读 SQL 和批量导入导出保留。
- 2.0.0 不再把用户名返回浏览器；编辑时用户名和密码留空都表示保留宿主端原值。
- 新导出包不含用户名和密码；覆盖导入不会用空凭据清除目标环境已有凭据。
- 连接仍被数据集引用时禁止删除，需先迁移或删除对应数据集，避免形成失效语义资产。
- 数据集和关系每次修改都会增加 `semanticVersion`（语义版本），供其他插件识别上下文变化。

## 6. 首次配置顺序

1. 在“连接管理”新建连接，输入用户名和密码并测试。
2. 保存后凭据不再显示；需要修改时重新输入，新值为空则保留原值。
3. 进入“数据集 → 新建数据集”，按“来源连接 → 来源数据库 → 来源表”逐级下拉选择。连接下的库和库下的表自动加载；选表后自动读取真实字段类型、字段注释和表注释，不用手填库名/表名。已配置默认库或只有一个可访问库时会自动展开。
4. 填写数据集名称（必填，最多 200 字符）。来源连接、数据库、表也标为必填；选表并成功读取字段后即可保存。表用途、字段业务名称、自定义注释和统一语义概念均为选填，可保存后再完善。点击“保存数据集”会列出未填项并定位到对应输入框；补填后提示自动消除。加载中或失败时按页面提示等待或重试，保存失败会保留当前填写内容。
5. 至少创建两个数据集后进入“关系拓扑”，按业务主题创建一个或多个拓扑。
6. 使用规则引擎、大模型辅助或手动添加关系。
7. 检查字段端点、关系基数和业务依据，人工确认正确关系。
8. 只有上述人工确认关系会被其他插件和智能体读取。

### 6.1 批量使用数据库字段注释

字段读取完成后，在“字段定义”上方点击“复制到业务名称”或“复制到自定义业务注释”。操作作用于当前表的全部字段行（包括未启用或标为敏感的行），但不改变行的启用/敏感标记。

- 默认“仅填空白项”，已编辑的内容会保留；若需替换，选择“覆盖已有内容”，点击目标按钮后确认覆盖数量。
- 没有数据库注释的字段跳过，不会复制页面占位文字，也不会清空已有内容。
- 业务名称最多200字符、自定义业务注释最多5000字符；超长字段保持原样并列出提示，须手工精简。业务名称为单行，复制时原换行转为空格。
- 复制结果只在当前编辑表单中，仍可修改；点击“保存数据集”后正式保存并提供给语义上下文。退出未保存表单不会自动落库，数据库原始注释始终不变。

## 7. 安装验收

### 7.1 页面

- 设置或“我的插件”中出现“数据库连接”。
- 顶部有“连接管理 / 数据集 / 关系拓扑”三页。
- MySQL 和 ClickHouse 操作一致，无“停用连接”按钮。
- 编辑已保存连接时用户名和密码为空，卡片和页面不显示原值。
- 数据集字段表中“数据库字段”和“字段类型”是两列。
- 新建数据集的来源库、表均为真实目录下拉选项；上级变更后清空下级旧选择，目录或字段读取失败时显示重试入口，不能带旧字段保存。
- 规则识别、大模型识别和手动添加关系位于当前拓扑选择区下方。

### 7.2 宿主接口

- `GET /api/database-connections/list` 不返回 `username` 或 `password`。
- `GET /api/database-connections/semantic/state` 返回数据集、语义概念、关系、拓扑与模型选择，不返回凭据。
- `GET /api/database-connections/semantic/snapshot` 只返回启用数据集、非敏感字段和人工确认关系。

### 7.3 智能体工具

在 Harness 工具清单中确认以下五个工具存在：

- `list_database_datasets`（列出数据库数据集）
- `get_database_semantic_context`（按问题获取精简语义上下文）
- `search_database_dataset_fields`（分页检索可用字段）
- `find_database_join_path`（查找数据库关联路径）
- `query_database_dataset`（查询数据库数据集）

先调用列出工具取得真实 `datasetId`（数据集标识），再测试上下文和最多 20 行只读查询。

### 7.4 日志

验收期间浏览器 Console（控制台）和 Harness 日志中不应出现插件加载失败、重复工具标识、配置校验错误或未处理异常。

## 8. 权限建议

- MySQL：只授予目标 schema（数据库模式）的 `SELECT`（查询）权限，以及读取 `information_schema` 中表结构所需权限。
- ClickHouse：只授予目标数据库及 `system.databases/system.columns/system.tables`（系统库/字段/表元数据）所需读取权限。
- 目录仅展示当前账号可见的库表。空目录时请检查权限或刷新，网络错误时先检查连接与网络；插件不会伪造库表，也不会绕过数据库权限。来源仍采用严格标识符校验，支持字母/下划线开头，后续为字母、数字、下划线、美元符或连字符的名称；包含其他字符的名称会明确报错，不能通过手填绕过。
- 不建议使用 root（超级管理员）或拥有写权限的生产账号。
- 数据集浏览可逐页取完，连接管理手写SQL仍最多返回200行；数据库权限仍是最终安全边界。

## 9. 回滚

1. 停止 Harness。
2. 删除或移除 2.0.0 插件：

   ```powershell
   dsh plugin --profile web remove @deepseek-ai/dsh-database-connections
   ```

3. 重新安装备份的 1.0.0 `.tgz`，或恢复备份插件目录。
4. 如 1.0.0 无法读取扩展后的设置文档，先恢复升级前备份的 `database-connections` 设置段。
5. 重启 Harness 并重新检查连接列表、测试连接和浏览数据。

不要仅覆盖 `lib/client.js`（浏览器端）或仅覆盖 `lib/index.js`（宿主端）；两半版本不一致会导致接口不匹配。

## 10. 常见问题

### 2026-08-27 按需上下文修订的操作入口

1. 数据集 → 预览大模型上下文，默认进入“按问题预览”。输入问题，选择全部/当前数据集/拓扑范围和单次预算，再生成预览。此过程不调用模型，不消耗模型生成额度。
2. 看本次选入的表、字段、确认路径和估算长度；展开“补选字段”勾选所需内容后重新生成。超预算时缩小范围、拆问题或在模型余量允许时提高预算，不会返回残缺语义。
3. “完整详情”可切换数据集，搜索/分页查看全部公开字段，展开原始来源和完整结构化内容；这些完整资料不会自动整份发给模型。
4. 关系拓扑 → 大模型识别关系 → 先查看分批计划。未配置模型也能看计划；配置后点击“识别此批”才调用一次模型。候选仍需人工确认。
5. 本次同时更新浏览器和后端运行代码，需要重启 Harness；不需要迁移设置数据。旧完整跨插件接口仍可用，模型工具新返回结构的适配见设计文档第9.4节。
6. 回滚本轮应安装 `database_2.0.0_语义按需上下文开发前_20260827_174049.tgz` 或恢复对应源文件备份，不需要回退至旧1.0.0。先备份当前设置；本轮未改存储结构，通常只回退代码即可，避免恢复旧设置覆盖用户新增数据。

- 大模型按钮不可用：先检查 Harness 是否提供 `llm`（大模型）服务，并在关系拓扑页选择真实模型服务与模型；规则引擎不受影响。
- 数据集读取不到字段：检查账号是否能访问目标数据库，以及是否能读取 `information_schema` 或 ClickHouse `system.columns`。
- 关系没有进入语义上下文：候选关系必须补充业务依据并人工确认；拒绝、候选和存在硬阻断的关系不会发布。
- 跨数据库关系是否自动联表：不会。插件提供关联路径和语义规划；真实查询工具一次只查询一个数据集，跨库组合应由上层插件分步执行并显式处理。
