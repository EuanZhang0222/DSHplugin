# 数据库连接插件 —— 安装与使用说明

本插件为 DeepSeek Harness（DSH）增加「数据库连接」能力：在 **设置页左侧** 新增一个
「数据库连接」切换按钮，用于管理 MySQL / ClickHouse 数据库连接，支持连接信息的
增删改查、自定义连接名称、测试连接通断，以及浏览数据库 / 表、执行只读查询。

---

## 一、交付物

| 文件 | 说明 |
|---|---|
| `deepseek-ai-dsh-database-connections-1.0.0.tgz` | 插件压缩包（标准 npm tarball），可在任意 DSH 电脑上安装 |
| 本说明文档 | 安装与使用指引 |

---

## 二、前置条件

- 已安装并可运行 DeepSeek Harness（Web 版，即 `dsh web` / `--profile web` 启动的界面）。
- 本机 `pnpm` 可用（DSH 的插件安装底层走 pnpm）。若随 DSH 自带了 pnpm，可直接使用。
- 目标电脑能访问 MySQL / ClickHouse 服务器（仅在使用连接功能时才需要）。

> 说明：插件的 HTTP 接口依赖 web 应用层（`webServer` 服务），因此请安装到
> **web profile**（即你平时用浏览器打开的 DSH），而不是仅安装到 headless/base profile。

---

## 三、安装步骤

### 方式 A：命令行安装（推荐）

1. 把 `deepseek-ai-dsh-database-connections-1.0.0.tgz` 复制到目标电脑（任意目录）。

2. 打开终端，切换到 DSH 安装目录（即含有 `apps/cli/lib/bin.js` 的目录），执行：

   ```bash
   dsh plugin --profile web add ./deepseek-ai-dsh-database-connections-1.0.0.tgz
   ```

   或使用绝对路径：

   ```bash
   dsh plugin --profile web add "C:/path/to/deepseek-ai-dsh-database-connections-1.0.0.tgz"
   ```

   > 若 `dsh` 命令不在 PATH 中，可用等价的 node 调用：
   > ```bash
   > node <DSH安装目录>/apps/cli/lib/bin.js plugin --profile web add ./deepseek-ai-dsh-database-connections-1.0.0.tgz
   > ```

3. 安装完成后，插件会自动写入 web profile 的 bundle 清单。**重启 DSH**（关闭并重新
   启动 `dsh web`，或重启你的 DSH 启动脚本）使插件生效。

4. 重启后，打开 DSH 网页 → 左下角「设置」，左侧导航栏会多出「数据库连接」一项。

### 方式 B：图形界面（若你的 DSH 提供插件管理页）

部分 DSH 版本在「设置 → 插件」中提供插件安装入口，可上传 `.tgz` 安装。安装后同样需要
重启 DSH 生效。

---

## 四、验证安装是否成功

重启 DSH 后，打开 **设置** 面板，确认左侧导航包含：

```
通用设置 · 模型 · 插件 · Agent 预设 · 数据库连接
```

看到「数据库连接」即表示安装成功。

命令行可进一步验证挂载（可选）：

```bash
dsh web --dump-config | grep -A2 database-connections
```

应能看到 `database-connections` 行。

---

## 五、使用方法

1. 打开 DSH → 左下角 **设置** → 左侧点选 **「数据库连接」**。

2. **新建连接**：点「新建」，填写：
   - 连接名称（自定义，例如「生产库 MySQL」）；
   - 数据库类型（MySQL / ClickHouse）；
   - 主机地址、端口（切换类型时会自动填默认端口：MySQL=3306、ClickHouse=8123）；
   - 用户名、密码；
   - 默认数据库（可留空）。

3. **测试连接**：填好后点「测试连接」，页面会显示「连接成功」或具体错误（如
   `Access denied for user ...`、`ECONNREFUSED`）。

4. **保存连接**：点「保存连接」后，连接进入左侧「已保存的连接」列表；点击列表项可
   重新载入编辑。编辑时密码留空表示不修改原密码。

5. **删除连接**：选中连接后点「删除」。

6. **读取数据（只读查询）**：
   - 点「浏览数据库」列出所有数据库；
   - 在下拉中选择数据库，列出其下所有表；
   - 选择表会自动生成 `SELECT * FROM <表> LIMIT 100`，或手动输入 SQL 后点「执行查询」。
   - 结果以表格展示。

7. **批量导出与导入**：
   - 勾选需要迁移的连接，点击「导出选中」得到 `.dshconfig.json` 配置文件；
   - 在另一套已安装相同插件的 DSH 环境选择冲突策略，再点击「导入配置」选择文件；
   - 「跳过已有项」保留目标配置，「覆盖已有项」更新同名/同 ID（唯一标识）连接，
     「创建导入副本」会保留两份并自动生成新的名称和 ID；
   - 导出文件不包含数据库密码。导入后逐项补填密码并执行「测试连接」；覆盖已有连接时，
     目标环境里原先保存的密码会保留，不会被空值清除。

> 安全约束：查询仅允许 `SELECT / SHOW / DESCRIBE / EXPLAIN / WITH` 开头的只读语句，
> 结果最多返回 200 行，避免误执行写操作或拉取巨量数据。

---

## 六、连接信息存储位置

所有连接信息持久化在 DSH 的 settings 文档中（`$DSH_HOME/settings.yaml` 的
`database-connections` 命名空间）。**密码以 secret 标记存储**，不会通过界面接口
明文回传（列表接口自动脱敏，仅返回 `hasPassword` 标记）。

---

## 七、卸载

```bash
dsh plugin --profile web remove @deepseek-ai/dsh-database-connections
```

然后重启 DSH。卸载会移除设置页的「数据库连接」入口与插件的 HTTP 接口；已保存的
连接信息保留在 settings 文档中，如需彻底清除可手动删除 `$DSH_HOME/settings.yaml`
中的 `database-connections` 段。

---

## 八、常见问题

- **Q：安装后设置页没有「数据库连接」？**
  A：需要**重启 DSH**（插件加入 bundle 清单后重启才生效），并确认安装到的是 web
  profile 而不是 base/headless profile。

- **Q：测试连接提示 `Access denied`？**
  A：用户名或密码不正确；MySQL 的 `root` 常见配置只允许本地 socket 登录，可用
  127.0.0.1 + 正确的账号密码，或为远程账号授权。

- **Q：ClickHouse 测试总是失败？**
  A：确认 ClickHouse 的 HTTP 端口（默认 8123）已开放，且账号 / 数据库名正确。
  插件使用 HTTP 接口连接 ClickHouse，并会真正校验账号密码。

- **Q：中文连接名称乱码？**
  A：插件内部使用 UTF-8 存储与传输。若通过命令行 curl 测试出现乱码，多为终端编码
  问题；在 DSH 网页界面中填写中文名称是正常的。
