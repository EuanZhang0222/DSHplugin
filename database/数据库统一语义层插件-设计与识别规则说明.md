# 数据库统一语义层插件 2.1.0——设计与识别规则说明

## 1. 设计目标

插件把“数据库连接”扩展为统一的底层数据语义层，使 Harness 中的其他插件和 Agent（智能体）能够知道：

- 有哪些可用的业务数据集；
- 每个数据集来自哪个连接、数据库和物理表；
- 表在业务中承担什么角色；
- 每个字段的数据库类型、数据库原始注释和人工业务解释；
- 不同表的字段是否表达相同业务概念；
- 哪些字段关系已经被人工确认，可以用于查询规划；
- 如何通过受控工具查询真实数据，而不暴露凭据、敏感字段或任意 SQL（结构化查询语言）执行能力。

插件不把大模型当作数据库事实来源。大模型和规则引擎只负责发现候选，人工确认才是发布门禁。

## 2. 分层模型

### 2.1 连接层

保存 MySQL（关系型数据库）或 ClickHouse（列式分析数据库）的连接参数。用户名和密码只在宿主端保存，均标记为 secret（密钥字段）；浏览器列表只收到 `hasUsername/hasPassword`（是否已保存凭据）布尔值。

### 2.2 数据集层

一个数据集固定指向一个 `connectionId + database + table`（连接标识 + 数据库 + 表）。数据集保存：

- 自定义数据集名称；
- 数据库表原始注释；
- 人工填写的表用途；
- 元数据版本哈希；
- 是否启用；
- 字段清单及字段级语义。

保存交互只要求名称（去掉首尾空白后 1–200 字符）、有效连接/库/表和成功读取的字段。界面用“* 必填”标注四项，业务用途、字段业务名称、自定义注释与统一概念不设必填门槛。缺项时保存按钮可点击，客户端会阻止请求并展示逐项汇总、字段错误和首个问题定位；输入修正后重新计算提示，不保留过期错误。加载中、元数据失败或来源不一致也不能提交，但会解释原因。保存中的同步防重入标记和按钮禁用共同避免重复请求；后端仍重新检查真实结构和原有约束，失败时保留当前编辑内容。

同步数据库结构时，以字段名合并：数据库类型、注释、键和索引状态以数据库当前定义为准；业务名称、自定义注释、统一语义概念、启用与敏感标记保留。

创建流程采用“连接 → 数据库 → 数据表”的级联目录，只调用真实 `/databases`、`/tables` 与 `/semantic/datasets/inspect`（库目录、表目录和字段检查）接口；选表后自动读取字段，不允许自由输入来源。每次变更撤销旧请求并增加请求轮次号，即使旧网络响应晚到也不能覆盖新选择；上级变更会清空下级旧结构。刷新同一来源时保留人工语义，已经消失或失权的选项被清空，错误与未完成读取均阻止保存。

默认库/预选表必须存在于真实可访问目录中；仅一个可见库时自动展开，否则等待用户选库。目录和字段读取分别提供加载、空值与重试状态，不缓存或伪造不可访问的表结构。标识符仍严格校验，额外兼容含连字符的库表名称，并在查询中按独立标识符引用。

### 2.3 统一语义概念层

统一语义概念用于说明不同字段名可能表达同一业务含义，例如 `meter_id`（电表标识）和 `meter_code`（电表编码）都可绑定“计量设备标识”。概念含名称、定义和别名。

绑定同一概念只是语义证据，不等于关系事实。能否关联还需检查字段类型、唯一性、外键、值覆盖和业务场景。

### 2.4 关系资产层

关系保存两个完整端点：

`datasetId / connectionId / database / table / field`（数据集标识 / 连接标识 / 数据库 / 表 / 字段）。

关系还保存：

- 基数：一对一、一对多、多对一、多对多；
- 来源：数据库外键、规则引擎、大模型辅助或人工维护；
- 状态：候选、人工确认、拒绝；
- 置信度、规则版本、模型与提示词版本；
- 业务说明、硬阻断和逐项证据。

### 2.5 拓扑层

拓扑是业务主题视图，不复制数据集或关系事实。一个数据集和一条共享关系可以被多个拓扑引用。数百张表可拆成“能源计量”“园区空间”“设备运维”等多个拓扑；无关联表无需强行放入同一拓扑。

规则引擎、大模型识别和手工添加都严格作用于当前选中的拓扑。

### 2.6 发布语义上下文

发布上下文只包含：

- 已启用数据集；
- 已启用且未标记敏感的字段；
- 数据库注释和人工业务语义；
- 已启用拓扑；
- 已人工确认的关系。

明确排除用户名、密码、敏感字段、候选关系、拒绝关系和停用数据集。插件不提供“大模型就绪度”或“大模型可用评分”，避免用不可验证的总分掩盖具体缺失项。

## 3. 规则引擎

### 3.1 版本和总分

当前规则版本：`relation-rules/1.0.0`（关系规则 1.0.0）。常规候选按 100 分模型计算：

| 证据项 | 权重 | 计算方式 |
|---|---:|---|
| 数据库约束与键结构 | 30 | 外键精确命中 30；否则目标唯一键 20、来源索引 5、两侧标识特征 5 |
| 统一语义与业务注释 | 25 | 同一统一语义概念 15；数据库注释/业务名称/自定义注释相似度最多 10 |
| 字段类型兼容性 | 15 | 类型完全一致 15；同类型族 12；UUID 与字符串显式可转换 8 |
| 字段名称与别名 | 10 | 对字段名分词、标识别名归一后计算 Jaccard（集合交并比）相似度 |
| 脱敏值匹配 | 15 | 去重值覆盖率：≥98% 为15，≥90% 为12，≥75% 为8，≥50% 为4 |
| 当前拓扑范围 | 5 | 两张表都属于当前选中拓扑 |

阈值：

- 高可信：85 分及以上；
- 中可信：70–84 分；
- 低可信候选：55–69 分；
- 55 分以下不保存为候选。

数据库真实声明的外键使用确定性覆盖：对外置信度记为 100，同时保留原100分证据明细中的实际加总 `weightedScore`（加权分）以便审计。外键依然先进入候选，必须人工确认后发布。

### 3.2 类型族

规则把数据库类型归为 numeric（数值）、string（字符串）、temporal（时间）、boolean（布尔）、binary（二进制）、uuid（通用唯一标识）或其他明确类型。MySQL 长度和精度不会改变类型族；ClickHouse 的 `Nullable`（可空）和 `LowCardinality`（低基数）包装会先展开。

时间与字符串、数值与时间等类型族不兼容时直接硬阻断。插件不会因为字段名相似而忽略类型冲突。

### 3.3 关系基数

关系基数依据键唯一性确定，不交给大模型自由猜测：

| 来源字段唯一 | 目标字段唯一 | 基数 |
|---|---|---|
| 是 | 是 | 一对一（1:1） |
| 否 | 是 | 多对一（N:1） |
| 是 | 否 | 一对多（1:N） |
| 否 | 否 | 多对多（N:N）候选，并触发硬阻断 |

两侧均不唯一时不能直接确认，通常应寻找中间映射表。人工可修改端点和关系，但不能绕过字段类型不兼容等数据安全校验。

### 3.4 脱敏值匹配

启用后，插件从两端各读取最多 1000 个非空去重值。原始值仅在宿主内存中短暂存在，立即计算 SHA-256（安全哈希）；模型、HTTP 响应和持久化配置只获得数量与覆盖率。

来源覆盖率公式：

`两端哈希交集数 ÷ 来源字段去重值数`

当来源样本不少于20且覆盖率低于20%时硬阻断。达到1000个去重值时记录 `truncated`（已截断），提示该统计不是全表证明。

### 3.5 硬阻断

以下情况不会形成可确认候选：

- 字段类型族不兼容；
- 脱敏值覆盖率低于20%且样本不少于20；
- 两侧均不是已知唯一键，试图直接建立一对多或多对一；
- 字段已标记敏感；
- 任一数据集不在当前拓扑；
- 大模型返回了拓扑字段白名单之外的端点。

所有自动结果默认状态均为 `candidate`（候选）。

## 4. 大模型识别关联关系

当前提示词版本：`relation-llm-prompt/1.1.0`（关系识别提示词 1.1.0）。

### 4.1 输入

模型只收到当前拓扑范围内的：

- 数据集标识、名称、用途、数据库、表和表注释；
- 启用且非敏感字段的名称、类型、数据库注释、业务名称、自定义注释、统一语义概念、键和索引状态；
- 统一语义概念定义和别名；
- 规则引擎候选、分数、硬阻断和证据。

识别先规划跨表字段分片，按单批输入预算组装；每批最多两张表、每表最多30字段，规则证据按剩余预算最多补充8条，模型最多返回100条。所有跨表字段组合都有对应批次，不再静默取前80表/500字段；过长单字段或表用途会明确阻断该批次。详细分批/预算规则见第9节。

用户名、密码、主机凭据和数据库原始数据不会发给模型。只有用户主动勾选“脱敏值匹配”时，服务端先计算统计值；模型也看不到原始值或哈希集合。

### 4.2 模型约束

系统提示明确要求：

- 不得编造数据集、表或字段；
- 同一统一语义概念不能直接等同于可关联；
- 有硬阻断的规则候选只能拒绝；
- 只能输出 JSON（结构化数据）；
- 关系类型只能是预定义四类；
- 必须给出中文业务依据；
- 结果只作为候选。

模型可以在规则候选之外提出新字段对，但两端必须存在于本次拓扑字段白名单。

### 4.3 服务端复核

模型输出依次经过：

1. JSON 结构和条数校验；
2. 数据集与字段白名单校验；
3. 重复关系去重；
4. 字段类型与键结构确定性重算；
5. 可选脱敏值覆盖率重算；
6. 硬阻断检查；
7. 写入候选关系并记录模型服务、模型名、提示词版本和规则版本；
8. 人工检查和确认。

模型给出的“置信度”不会直接采用；最终显示的置信度来自服务端确定性规则。

### 4.4 失败处理

- 未配置 `llm`（大模型）服务：返回可理解错误，不影响规则引擎。
- 未选择模型服务或模型：阻止调用。
- 超时：默认60秒后取消。
- 达到最大输出长度、请求中止、模型尝试调用工具或返回非法 JSON：本次识别失败，不写入部分结果。
- 模型输出端点越界：整批拒绝，防止幻觉字段进入关系资产。

## 5. 人工确认与修改

人工关系编辑器同时展示：

- 数据集名称；
- 数据库和数据库表；
- 字段名和字段类型；
- 数据库注释；
- 人工业务名称与自定义注释；
- 统一语义概念。

人工确认前必须填写关系依据与业务说明。确认会记录时间和确认来源；编辑已确认关系后重新保存会重新计算状态和端点。删除关系会同时从所有拓扑引用中移除。

## 6. 其他插件与智能体调用

### 6.1 宿主服务

插件通过 Cordis（插件上下文）提供 `databaseSemanticLayer`（数据库语义层）服务，版本 `1.2.0`：

- `listDatasets`（列出数据集）
- `getDatasetContext`（获取数据集上下文）
- `getTopologyContext`（获取拓扑上下文）
- `findJoinPath`（查找确认关系路径）
- `queryDataset`（受控查询单个数据集）
- `getSnapshot`（获取发布快照）

其他插件不得直接读取本插件 settings（设置）文档，避免依赖内部存储结构和接触凭据。

### 6.2 智能体工具

五个工具采用稳定静态名称，不按每个数据集动态注册，避免数据集增删导致 Harness 工具表不停变化或重启要求。调用方先列出数据集取得标识，再获取语义、路径或查询数据。

### 6.3 查询安全

`query_database_dataset`（查询数据库数据集）不接受原始 SQL。服务端：

- 按数据集字段白名单验证选择、过滤和排序字段；
- 拒绝敏感或停用字段；
- MySQL 使用 `?` 参数，ClickHouse 使用带类型参数；
- 支持 `eq/ne/gt/gte/lt/lte/in/like/is-null/not-null`（等于/不等于/大于/大于等于/小于/小于等于/集合/模糊/为空/不为空）；
- 最多1000个可查询字段、20个过滤条件、5个排序条件；200为每页最大行数，不是总结果上限（2.1.0起，见第10节）；
- 标识符按数据库方言引用，并限制为合法数据库标识。

查找关系路径只返回人工确认关系，不自动执行跨库联表。跨连接查询需要上层插件按路径分步查询、显式合并并处理一致性。

## 7. 持久化与并发

### 7.1 数据库注释复制的编辑与保存边界

复制是确定性的界面编辑操作，不调用大模型、不额外查询数据库。源值取自当前数据集字段的 `databaseComment`（数据库原注释），目标仅允许 `businessName`（业务名称）或 `customComment`（自定义业务注释）。两个目标互不影响，字段名、类型、数据库原注释、启用/敏感标记及统一语义概念均保留。

规则顺序：无原注释则跳过；默认模式下目标已有非空内容则保留；去除原注释首尾空白，业务名称内部换行转空格；按服务端相同的200/5000字符限制检测，超长保持原值且列出字段；相同值不重复修改；其余写入当前草稿。空白字符组成的目标视为空项。覆盖模式只在确有非空旧值需要替换时弹出确认，不因无注释或超长而清空旧值。

作用范围为当前表全部字段行，包含暂未启用及敏感行，但这些标记不改变；发布语义上下文时仍沿用原有字段筛选边界。原注释不是经过人工确认的语义解释，批量复制不会自动确认拓扑关系，也不会绕过人工审核。切换来源后旧字段与复制提示清空；加载中不可复制。确认复制不发保存请求，只有用户点击“保存数据集”后，才进入原串行持久化、版本和审计流程。

### 7.2 原有持久化约束

- 所有语义写操作进入串行写队列，避免并发 `scope.replace`（配置替换）相互覆盖。
- 每次成功写入增加 `semanticVersion`（语义版本）。
- 审计日志保留最近500条。
- 单个配置支持最多500个数据集、每数据集1000字段、2000统一语义概念、10000关系和200拓扑。
- 删除连接、数据集、概念、关系和拓扑都有引用处理或显式级联门禁。

## 8. 兼容性边界

- 旧 1.0.0 连接配置自动补语义默认值，不要求一次性迁移。
- MySQL 元数据来自 `information_schema.COLUMNS/STATISTICS/KEY_COLUMN_USAGE/TABLES`（字段/索引/外键/表信息）。
- ClickHouse 元数据来自 `system.columns` 和 `system.tables`（系统字段和表）；旧版本缺少表注释列时降级为空注释，不影响字段读取。
- ClickHouse 没有通用外键和唯一约束语义，因此更多依赖业务注释、统一语义、排序键、脱敏值和人工确认。
- 浏览器端和宿主端必须同时升级到2.0.0。

## 9. 按需语义与上下文预算（2026-08-27）

### 9.1 页面与真实调用分开

“完整详情”只读取当前数据集的公开完整资料，字段每页12条，数据库原注释与自定义说明可展开核对，结构化全文默认折叠。左侧目录独立分页且不随右侧内容等高拉伸。“按问题预览”不调用模型、不读取业务行数据，只运行与智能体相同的任务语义构建器；页面预算不包含真实会话历史，不能冒充实际模型计量结果。切换详情后保留本次问题和结果。

### 9.2 检索与字段选择的确定性规则

1. 只检索启用数据集、现存连接和启用且非敏感字段。检索范围可以是全部数据集、指定数据集或一个启用拓扑；无效拓扑直接报错，不回退到全库。
2. 问题使用大小写/全角归一，英文及数字按词匹配，中文使用连续短语和相邻双字词；排除“查询、什么、数据、信息”等通用双字词。这是本地词法检索，不是向量检索，也没有调用模型偷偷改写问题。
3. 单文本分数：包含完整问题加10；命中长度大于2的词加3，否则加1。数据集的名称/用途/库/表/表注释文本得分乘2，再加字段最高分。字段检索同时使用字段名、业务名称、自定义/原注释、概念名称/定义及别名；同分按数据集标识稳定排序。分数只用于排序，不是业务正确率或“大模型就绪度”。
4. 未指定数据集时最多选前5个匹配项，并明确提示未选入数量；指定时支持1～8个。没有问题且没有指定数据集时返回“需选择”，绝不整份载入拓扑。
5. 保留问题命中的字段，以及主键、名称包含 tenant/org/unit/time/date/status/enabled（租户/组织/单位/时间/日期/状态/启用）的字段，或注释中的单位、时间、日期、租户、启用状态字段。不自动推断具体租户值或过滤条件。此启发式不能保证识别所有特殊业务口径，调用方应检查用途并通过补查接口选字段。
6. 在所选数据集之间寻找已确认路径，加入中间表及关系两端字段，同时保留选中表之间的直接确认关系。无路径会列出不连通项，不能猜测关联。语义概念相同本身不构成关联事实。
7. 字段解释优先自定义说明，否则用数据库原注释；业务名称与解释完全相同时只输出一次。只输出被使用的概念，概念定义集中存一份。保留来源连接标识/名称、数据库与表；省略审计时间、索引等无关管理信息。原数据库注释、自定义资料和旧完整接口均不删除。

分页游标绑定语义版本、问题和范围；资料变更或换条件后，旧游标报409并要求从第一页重新检索。页面每页8个目录/10个补查字段，接口默认12、上限30。字段可以在结果卡片中补选后重新生成；不要求用户手写字段名。

### 9.3 预算与失败边界

- 单次语义预算默认6000，允许1024～16000个估算 Token（文本计量单位）；界面提供2000/4000/6000/8000/16000档。
- 发送前估算规则：ASCII（基本拉丁字符）每字符计1/3，其他字符每字符计1.5，再加32余量；统计整个紧凑工具返回封套。不是某个模型的精确分词器或计费口径。
- 智能体实际调用时读取 `agent.session.requestHeader()`（会话请求配置）、`tokenMeter.measure(session)`（宿主会话计量）和 `llm.resolveModelInfo()`（模型窗口）。回答预留取4096与配置输出上限的较大值，安全预留取2048与窗口5%的较大值。
- 可用语义预算 = min（本次上限，模型窗口 − 宿主已用量 − 尚未反映到日志的本插件返回预留 − 回答预留 − 安全预留）。同一会话日志版本的连续工具结果会累加预留；日志/计量变化后重新计量。检索和上下文工具声明非并发安全，避免同批工具各自重复占用可用空间。
- 宿主缺少窗口/计量时标注 `fallback`（降级），只按单次上限控制，不能保证整个会话一定容纳。页面标注 `standalone`（独立预览）；真实计量标注 `session`（会话预算）。没有修改宿主核心对话循环；其他插件输出、查询结果和历史压缩仍由宿主管理。
- 超限返回 `budget_exceeded`（预算不足）、估计需要量和缩小范围建议，不返回截断的字段/关系。不以删掉关键关联键、截半句业务含义来假装成功。诊断消息本身仍占少量上下文；会话完全没有余量时应由宿主压缩或开启新会话。

### 9.4 跨插件接口与迁移

服务 `databaseSemanticLayer`（数据库语义层）版本1.1.0新增：`searchDatasetCatalog`（检索目录）、`searchDatasetFields`（检索字段）、`prepareTaskContext`（构建任务语义）。旧 `listDatasets/getDatasetContext/getTopologyContext/getSnapshot` 完整接口保持形状，适合管理和显式获取资料；接入模型时应迁移到新接口，不能继续把完整快照拼进提示词。

HTTP（网页接口）新增 POST `/semantic/context/catalog`、`/semantic/context/fields`、`/semantic/context/task`，均在 `/api/database-connections` 前缀下。任务参数包括 `question`（问题）、`datasetId/datasetIds`（选定数据集）、`topologyId`（范围）、`includeFields:[{datasetId,field}]`（补选字段）、`maxTokens`（预算）。接口返回 `{result}`，内含与工具相同的封套。类型见 `lib/types/index.d.ts`。

工具 `list_database_datasets` 保留 `datasets` 字段，增加 `total/nextCursor`（总数/后续游标）；`get_database_semantic_context` 改为 `{status,context,budget,selection}`，不是旧顶层 `dataset` 结构，使用旧形状的自动化消费者必须适配。新增 `search_database_dataset_fields`。正常顺序是检索目录 → 取当前问题语义 → 必要时补查字段 → 受控查询；无需每轮重复载入全部库表。

`status`（状态）可能为 ok（成功）、needs_selection（需要选择）、no_match（未命中）、budget_exceeded（超预算）。只有成功时才有语义内容，消费者须检查状态。跨插件调用若不传真实执行上下文，只能获得独立预算，不能伪造已做会话校验。

### 9.5 关系识别分批

按稳定的数据集标识顺序枚举所有跨表组合；每张表按输入预算分字段块、每块最多30字段，两个字段块组成一批。通过虚拟索引分页计算计划，不在内存中预生成海量提示词。不同表的全部公开字段组合均有批次覆盖，不再静默跳过前80表/500字段之外的资料；表内自关联仍通过手动维护。

默认单批输入预算8000，可选4000/16000；大拓扑的表对组合可能产生大量调用，计划页明确显示批次数，由用户逐批选择。规划不调用模型，执行一批才调用一次模型并可能计费，不会自动扫完整库。无模型配置时仍可看计划，执行按钮禁用并提示配置。

字段及表说明不截断，优先给它们预算；剩余空间按置信度补充最多8条确定性规则证据。缺少提示词内规则证据不意味着无关系，模型可以在本批白名单内建议新字段对。过长单字段/表用途导致批次超预算时，必须调整资料或预算，不能悄悄丢掉。实际执行额外检查所选模型窗口、输出预留及安全余量。

计划版本覆盖拓扑范围、表/字段语义和概念；候选关系写入不使计划失效，修改源资料会使旧计划失效。逐批保存候选、按字段对去重；执行中源资料改变、流异常结束、白名单不符或输出过长时本批不写入。模型基数与键结构复核不一致则拒绝该候选，必须人工维护。已确认/已拒绝关系不被模型覆盖。完成批次标记仅保留在当前窗口，候选关系本身持久保存；不是后台任务调度器或跨窗口断点队列。

## 10. 全量查询与分页完整性（2.1.0）

### 10.1 为什么不是简单增加返回行数

“全部”指当前数据集、已选择的可查询字段、过滤条件和数据库账号可见范围内的完整查询结果，不是解除敏感标记、读取所有数据库，也不是承诺无限数据能同时装入模型窗口。未指定fields（字段列表）时读取全部启用的非敏感字段，不再只取前12列。连接管理的手写SQL入口仍是人工诊断入口，保留200行/15秒限制。

首次调用执行一次没有总LIMIT（结果行数限制）的参数化只读SELECT。MySQL使用驱动行流，ClickHouse使用JSONEachRow（逐行结构化结果）流；逐行写入宿主临时目录，并写入定长磁盘索引。不把整个结果放入内存。后续页只读这份固定结果，不重新向数据库执行带偏移量的查询，所以没有主键、排序值重复及翻页期间增删数据都不会导致分页机制漏行或重复。

这不是跨库事务快照：源查询自身的一致性仍由数据库引擎、隔离级别、分布式表等决定。固定的是**该次SELECT实际返回的结果**，不是保证所有数据库某一时刻的全局一致视图。新记录要发起新查询才能看到。

### 10.2 调用协议与完成判定

智能体继续使用 `query_database_dataset`（查询数据集）；跨插件继续使用 `databaseSemanticLayer.queryDataset`（查询服务）；网页继续使用 POST `/api/database-connections/semantic/query/dataset`。三者走同一个结果缓存。

- 首次传datasetId（数据集标识）、可选fields/filters/orderBy（字段/过滤/排序）；limit现在仅为每页最多行数，默认100、最高200，总行数不受200限制。
- 后续传同一datasetId和上一页nextCursor（下一页游标）。不要改变字段、过滤和排序；条件变化须清空游标开启新查询。
- status（状态）：collecting=采集中，ready=采集结束，failed=采集失败，budget_exceeded=单页预算不足，closed=已释放。
- capturedRows是已成功落盘行数；采集未结束时totalRows为null，不能把当前数量说成总数；只有ready时totalRows才是准确结果行数。
- readThrough是此游标已读取至第几条，rows只属于当前页。complete只有“采集成功并且当前读取位置到末尾”才为true，此时nextCursor为null、hasMore为false。ready不等于调用方已经读完。
- cursor是当前页起点，重试相同cursor能重新读取这一页；nextCursor是后续位置，只有处理完本页才能推进。
- 页大小还受maxTokens（估算文本预算）影响。单行超出预算时返回rowFragment（行分片），包含rowNumber/offset/text/complete/encoding：按同一行的offset顺序拼接text，最后一片到达后解析JSON。不能丢弃分片，也不能把片段当完整记录。
- 未读完时工具说明要求模型继续翻页并记录进度。不能仅根据第一页编造全量总数、总量或完整性结论。模型是否遵循工具指令仍取决于实际执行；本插件提供可遍历全部结果的通道和可验证的完成标记，不承诺无限上下文或强制所有第三方模型执行完毕。

跨插件调用示例（processRows/processRow必须由调用方实现，按需写入自己的结果文件或流式计算，不要累计到对话中）：

```javascript
let request = { fields: ['id', 'value'], limit: 200 };
let cursorForClose, fragment = '';
try {
  for (;;) {
    const page = await service.queryDataset(datasetId, request, signal);
    cursorForClose = page.cursor || cursorForClose;
    if (page.status === 'failed' || page.status === 'budget_exceeded') {
      throw new Error(page.error || page.nextAction || '查询未完整完成');
    }
    await processRows(page.rows);
    if (page.rowFragment) {
      if (fragment.length !== page.rowFragment.offset) throw new Error('分片不连续');
      fragment += page.rowFragment.text;
      if (page.rowFragment.complete) { await processRow(JSON.parse(fragment)); fragment = ''; }
    }
    if (page.complete) break;
    if (!page.nextCursor) throw new Error('缺少后续游标，不能宣称完成');
    if (!page.rows.length && !page.rowFragment) await new Promise(resolve => setTimeout(resolve, 250));
    request = { cursor: page.nextCursor, limit: 200 };
  }
} finally {
  if (cursorForClose) await service.queryDataset(datasetId, { cursor: cursorForClose, action: 'close' });
}
```

### 10.3 权限、精度与资源边界

- 游标经随机密钥签名，绑定查询/位置和数据集；智能体侧还绑定可用的会话标识。游标是临时访问凭证，不能外发。源连接、数据集或字段敏感/启用状态改变时旧结果拒绝读取。
- 每次新查询都重新做字段、过滤、排序与参数化校验。只读业务数据库，不创建物理表、外键或写业务记录。
- MySQL大整数和小数保留字符串精度、日期保留数据库文本、JSON字段以文本返回；二进制值返回带base64（编码方式）标识的无损内容。ClickHouse要求64位整数和小数按字符串输出，并把结果/读取/超时溢出模式设为throw（报错），不能默认break（静默提前结束）。数据库不支持相应设置会明确失败。
- 每个运行实例默认最多8个缓存查询、合计1 GiB（约10.7亿字节）缓存、每次采集最长10分钟；缓存闲置1小时失效。这里限制的是运行资源，不是只让模型看到前若干行。超过限制会返回未完成或拒绝开启，不能把部分结果当全量。更大结果应按互不重叠的业务范围分批；这些保护值目前是服务端默认值，不提供页面配置。
- 界面关闭、action=close（关闭查询）、正常插件卸载及超时清理释放临时结果。进程异常终止后游标失效，临时文件可能残留在操作系统临时目录，需本机清理；不把缓存写进语义配置或安装包。
- 模型单次输出默认6000、允许1024～16000估算Token。若宿主提供会话用量与窗口，先扣除历史/回答/安全余量。预算不足时保留未推进游标、明确未完成；调用方需要释放上下文后继续，不能靠分页让无限数据同时留在模型记忆中。

### 10.4 兼容与本轮范围

网页完整分页器使用额外page（页码）参数，例如`{cursor, page:8, limit:200}`。查询先完成采集，准确totalPages（总页数）按`Math.ceil(totalRows / limit)`计算；0条记录为0页，采集中为null而不猜测。输入页码必须为范围内正整数，修改每页行数回到第一页。数字页码显示首尾和当前页附近页码，中间以省略号表示。

后端通过磁盘行索引直接定位`(page - 1) * limit`，游标中的固定页边界同样经过签名并重新检查权限；pageComplete（本页完整）与complete（已到整个结果末尾）分开。超长行或文本预算造成网络分片时，页面自动用pageNextCursor（本页续读游标）装配完整记录，不能把网络请求次数当成页数。浏览器只保留当前页，32MiB单页保护超限时明确提示减少页大小，不截断内容；模型接口仍可逐片读取。页码模式只供网页/服务调用方使用，模型工具保持顺序nextCursor协议；跳到末页不能证明之前各页已处理。

例如1507条数据：每页200行共8页，第8页是1401～1507条；每页50行共31页，第31页是1501～1507条。跳页不重新扫描源库，不改变固定查询结果。

原查询工具名称、HTTP路径、fields/filters/orderBy/limit输入及dataset/columns/rows输出保留；新增的异步采集状态、页游标和分片意味着旧调用方必须适配循环，不能忽略complete和rowFragment。本轮未修改持久化结构，不需要迁移已保存连接、数据集和关系。服务版本升级到1.2.0，插件升级到2.1.0。

本轮未增加聚合统计接口、任意SQL给模型执行、跨库联表执行、全量文件导出或模型自动汇总器。全量分页只负责提供完整、可继续读取的原始查询结果。

## 11. 当前明确不做

- 不自动修改数据库结构、创建真实外键或写入业务数据；
- 不把候选关系自动发布给大模型；
- 不提供无法解释的“大模型就绪度”总分；
- 不自动执行任意跨库 Join（关联查询）；
- 不绕过数据库自身权限；
- 不把统一语义等价直接当作字段可关联事实。
